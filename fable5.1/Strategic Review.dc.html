The Discovery Report is substantially accurate on facts and partially wrong on interpretation. Every architectural and code-level claim re-verified true. Two interpretations need revision:

Offering screens CashCountView, OfferingSessionList, OfferingDetailOverview already use .gl-card/.gl-table--cards/.gl-statgrid; only OfferingEntryForm, OfferingReviewSheet, VarianceResolutionView remain literal-heavy.

Confirmed: vanilla-TS stack; stale React-era DS guide (and a second stale artifact, mockups-extracted/github.md, mapping to non-existent src/routes/*.tsx); three status maps; duplicated transaction-row markup; off-scale literals in 3 offering files; string-asserting UI tests; no visual regression.

6. §12 decisions — options, trade-offs, recommendation

D1 · Radius / shadow / control heightNEEDS APPROVAL
Option A — canonise shippedUpdate tokens to card 16 · button 12/46px · input 12/46px · dialog 20; shadows: promote the two Modern literals to --shadow-card/--shadow-elevated. Zero pixel change; QA'd in production; matches every screenshot in docs/screenshots/live.
Option B — revert to DS tokensCard 24 · button 18 · dialog 28, faint shadows. Restores the React-era spec; visibly changes every route; contradicts an owner-approved commit 5 days old; no user has seen it in the vanilla app.
RecommendationA. The "identity" in the DS guide describes a product that no longer exists; the live app is the identity. Redesign plan then evolves from 16px as the base.
D2 · Canonical status labels/colorsRECOMMEND — confirm copy
posted"ลงบัญชีแล้ว" (Transactions) vs "บันทึกบัญชีแล้ว" (Approvals). Recommend "ลงบัญชีแล้ว" — shorter, the accounting verb, on the higher-traffic page. Variant: info (neutral-blue) not approved-green — posted is a ledger state, approved is a decision; conflating them hides whether money has actually moved.
voidedneutral vs rejected. Recommend neutral "ยกเลิกแล้ว" — a void is a reversal of a posted item, not a refusal; red should stay reserved for expense/rejected.
pending (dashboard)"รอตรวจสอบ" vs "รออนุมัติ". Recommend "รออนุมัติ" everywhere (matches the nav label คิวอนุมัติ).
D3 · Modal glassRECOMMEND — low stakes

Keep: "overlay material" argument in the app.css comment. Flatten: CLAUDE.md bans glass; blur(20px)+saturate costs GPU on low-end Android counters use on Sunday; DS says blur in exactly one place. Recommend flatten to solid --popover + --shadow-elevated; keep topbar blur. Backdrop can keep its 3px blur (cheap, aids focus).

D4 · Dark modeRECOMMEND — defer, keep tokens

Tokens are complete; no toggle exists; PREMIUM audit P2-9 notes literals would defeat it. Building it now doubles QA surface during a redesign. Recommend LATER: keep .dark tokens, add a DECISIONS entry, revisit after Phase 4 when literals are gone.

D5 · Where the DS livesRECOMMEND

design-system-extracted/ in-repo is what app.css imports and CLAUDE.md names — it is canonical by construction. The external DS project (this workspace's _ds/) should sync from the repo after Phase 2 changes tokens. No rename (path is referenced in 3 places).

D6 · Reports' tinted stat tiles vs white cardsNEW — surfaced by screenshots

Reports fills whole KPI cards and table headers with income/expense tint; Dashboard/Funds keep white cards and color only the number. Recommend white card + colored value as the single rule (DS: "max two background colors per screen"), reserving full tint for .gl-stat--danger variance warnings where alarm is the point.
