1. Executive summary

Grace Ledger already has a real, documented design system — not an implicit one. Tokens live in design-system-extracted/tokens/*.css, a class layer (.gl-*) lives in src/styles/app.css, and CLAUDE.md codifies the rules (one accent, fixed finance colors, border-over-shadow, 44px targets, 400ms ceiling, Thai copy rules). The identity is coherent and worth preserving.

The problems are not missing foundations; they are three specific forms of drift:

  • Two competing visual layers inside one file. app.css lines 1–~1000 define the token-faithful system (cards 24px radius, buttons 18px, faint --shadow-*). A later "Modern UI layer" block (line ~1050 onward) re-declares the same selectors with new literals: .gl-btn → 46px/12px, .gl-card → --radius-lg + a 30px shadow, page max 1080→1180px, sidebar 240→248px, topbar 56→64px. The design-system tokens for radius/shadow are therefore defined but overridden.
  • Inline-style screens that pre-date the class layer. The offering module (OfferingEntryForm.ts, OfferingReviewSheet.ts, VarianceResolutionView.ts) hand-writes cards, badges, headings and inputs with literals (24px, 13.5px, 12.5px, 11.5px, rgba(0,0,0,0.02), border-radius: 4px/6px/10px) instead of .gl-card, .gl-badge, .gl-page-header, .gl-input.
  • The attached design-system guide describes a different stack. It says React 19 + Tailwind v4 + shadcn/ui and maps to src/components/ui/*.tsx, src/routes/*. Those files do not exist on main. The live app is vanilla TypeScript + Vite with render*Html(): string functions (CLAUDE.md: "No React, no framework"). The DS tokens are still accurate; its component library and screen map are stale.

Recommended direction: consolidate, do not redesign. Resolve the two-layer conflict by making one deliberate decision per token, migrate offering screens onto the existing .gl-* classes, refresh the design-system's stack description and screen map, and add governance docs that point at code, not prose. All of this is CSS/markup-only; the financial core, RPCs, RLS and tests are untouched.

3. Current design system inventory

Colors — real token system: YES

  • Primitives --gl-* (white, bg #FFFCF8, ink #171717, stone 50/200/500, orange 50/600/700/900, emerald, amber, red, blue) → semantic (--background, --card, --border, --primary, --ring…) → finance (--income/--expense/--offering + -muted/-foreground, aliased to --pending/--approved/--rejected).
  • App-level addition --on-{income,expense,pending,info}-muted for text on muted surfaces — well-reasoned, documented in app.css and StatusBadge.ts. Should be promoted into the token package.
  • Hard-coded colors in src/: 44 matches, almost all shadow alphas (rgb(23 23 23 / …)) and 5 semantic tints in ProposalConfirmationModal.ts (rgba(245,158,11,…), rgba(239,68,68,…)) that should be --pending-muted/--expense-muted. One color: #ffffff in AppShell.ts:211.

Typography — systematic with local fragmentation

  • Scale: --text-2xs 11px → --text-6xl 52px; body 15px/1.6; headings --font-display (Inter) 600, −0.02em. .num-display for all money (tabular, lining, slashed-zero). .kicker eyebrow.
  • Off-scale literals: 13.5px, 12.5px, 11.5px, 14px, 24px, 10px — ~30 occurrences, all in components/offering/* and ProposalConfirmationModal.ts. Everything in pages/*, approvals/*, ai-drawer/* uses tokens.
  • Weight conflict: DS base.css sets headings to 600; app.css .gl-page-header h1 uses --weight-bold (700); offering screens hard-code --weight-bold on h1 at 24px.

Spacing — clean scale, one exception zone

  • 4px scale --space-1…24; table cells 20/12; --touch-target-min 44px. Pages/approvals/dashboard use tokens plus a few 2/3/4/6px micro-offsets (acceptable).
  • Offering module uses 22px 24px, 20px, 14px 18px paddings/margins — not on scale.
  • Layout tokens defined twice: --gl-page-max 1080 → 1180, --gl-page-pad-x --space-8 → clamp(16px,3vw,40px), --gl-sidebar-w 240 → 248, --gl-topbar-h 56 → 64, --gl-mobilenav-h 60 → 68. Second declaration wins; first is dead code.

4. Existing design patterns

App shellKEEP

240/248px sidebar with grouped nav + kicker group labels + 3px active bar; sticky blurred topbar (the one sanctioned blur); fixed bottom nav at ≤768px with badge. AppShell.ts. Strong, intentional, tested. Problem: its styles are split between an inline <style> and two app.css blocks; gradient on .gl-shell-mark/.gl-shell-avatar is then overridden with !important to flat orange.

Page headerIMPROVE

h1 + one-line p, optional right action. Used via .gl-page-header in Transactions, Funds, Members, Reports, CashCount, SessionList. Not used by Approvals (re-implements in .gl-section__head), OfferingEntryForm / ReviewSheet (inline 24px h1). Three implementations of one pattern.

Hero balance cardKEEP

Dashboard only. .gl-card--elevated: kicker → 40px .num-display → meta line → 2-col income/expense with border-top. The one "lifted" surface per screen, matches DS rule. Note it carries a radial orange gradient wash — the sole gradient in the product; decide explicitly whether it is the sanctioned exception (recommend: yes, document it).

Transaction rowMERGE

36px tinted icon tile + title/subtitle + right-aligned signed .num-display amount + tiny badge, inside a .gl-card with padding: 2px var(--space-4). Rendered twice with near-identical 40-line inline markup in DashboardPage.ts and TransactionsPage.ts. Direction → sign/color mapping duplicated too. Should be one renderTxnRowHtml().

Status badgeMERGE

approvals/StatusBadge.ts holds STATUS_CONFIG (posted → info "บันทึกบัญชีแล้ว"). TransactionsPage.ts holds a second TXN_STATUS map (posted → approved "ลงบัญชีแล้ว", voided → rejected "ยกเลิก"). Same status, two labels, two colors. Dashboard uses a third ad-hoc set ("รอตรวจสอบ"). Direct violation of CLAUDE.md single-source-of-truth.

Responsive data tableKEEP

.gl-table--cards: one markup, table ≥900px, stacked cards with data-label below. Used in OfferingSessionList, OfferingReviewSheet, OfferingDetailOverview. Well-built. Only tension: Modern layer adds border-radius: --radius-lg to .gl-table, contradicting the DS "tables are always 0px" rule.

Modal dialogIMPROVE

.gl-modal-backdrop + .gl-modal-content used in Transactions, Funds, Members, RejectionModal, ProposalConfirmationModal — consistent. But content is popover/88% + blur(20px) saturate(160%) glass, which the DS guide and CLAUDE.md ("banned: generic glass cards") both disallow. Escape/backdrop-click handling is re-implemented per page.

Quick-action gridKEEP

4 tiles, one primary (orange) + three muted, 2-line labels, 76→88px min-height. Dashboard only; asserted by tests (href, label text). Hover is translateY(-2px) — consistent with card hover language.

Stat stripKEEP

.gl-statgrid/.gl-stat with success/danger/warning tints for expected / counted / variance in cash count. Collapses to label–value rows at ≤768. Good.

Filter pillsIMPROVE

Transactions stacks filter-pill gl-btn gl-btn--sm gl-btn--primary|secondary + inline radius; app.css also defines a standalone .filter-pill.is-active that is never applied. Two competing active states — the primary-button one wins visually. Pick one.

Empty / error / loadingIMPROVE

Error → .gl-notice--error with retry (consistent). Loading → skeletons (Approvals) vs text-in-card (Transactions) vs nothing (Dashboard). Empty → .gl-card centered text with 3 different paddings. Copy is good and honest; presentation needs one renderEmptyStateHtml().

AI drawerKEEP

Right sheet 420px, token-pure stylesheet (aiDrawerStyles.ts), proposal cards with --warning border, provenance footer. The cleanest newer code in the repo — use it as the reference for how feature stylesheets should be written.

Interaction rules for Claude on this repo

  • Before any UI change: read DESIGN.md + COMPONENTS.md; grep for an existing class/helper; cite it in the plan.
  • Never add a second declaration of an existing .gl-* selector; edit the one that exists.
  • New literal px/hex/rgba in src/ = a DECISIONS.md entry or a rejected diff.
  • UI tests assert HTML strings — update tests deliberately with the markup, never loosen them.
