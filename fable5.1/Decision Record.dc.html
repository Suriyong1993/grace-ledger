1.1 ผู้รับผิดชอบและผู้ตรวจสอบที่ถูกต้องของคริสตจักร (Authorized Officers) CANONICAL

กำหนดให้บุคลากร 4 ท่านต่อไปนี้ เป็นผู้รับผิดชอบ ผู้ตรวจสอบ และตัวตนในระบบ (Identity & Governance Roster) เพียงชุดเดียวของ คริสตจักรพระคุณ กาฬสินธุ์ สำหรับการยืนยันตัวตน สิทธิ์การอนุมัติ การนับเงินสด และรอยตรวจสอบบัญชี (Audit Trail):

ตำแหน่งคริสตจักรชื่อ-นามสกุลสิทธิ์ในระบบภาระหน้าที่หลักในระบบการเงิน
ศิษยาภิบาลอาจารย์สรรเสริญ ดวงจิตรpastorอนุมัติคำขอเบิกจ่าย, ดูแลภาพรวมพันธกิจและความโปร่งใส, ปิดรอบการเงินประจำเดือน
ผู้นับเงิน (คนที่ 1)อาจารย์ ทัศนา ดวงจิตรcounterตรวจนับเงินสดถวายวันอาทิตย์ตามเกณฑ์สองคน (Dual-Counter Rule 4), คัดแยกธนบัตร/เหรียญ
ผู้นับเงิน (คนที่ 2)สุดารัตน์ จิณเซ่งcounterร่วมตรวจนับเงินสด, ตรวจสอบยอดซอง, ยืนยันผลนับเงินสดร่วมกับผู้นับคนที่ 1
ผู้ตรวจสอบบัญชีพณ.ท่านหม่อมราชวงศ์สุริยงค์ บาลเพ็ชรsuper_adminตรวจสอบบัญชีและการเงินทั้งหมด, สิทธิ์ผู้ดูแลระบบสูงสุด, อนุมัติการตั้งค่าและตรวจสอบ Audit Log

ข้อกำหนดการใช้งาน: ห้ามใช้ชื่อจำลองหรือ mock data อื่นใด (เช่น ศจ.สมชาย มีสุข, มนัส สุขใจ) ในเอกสารการออกแบบและหน้าจอ Mockup/Production ทุกส่วนต้องสอดคล้องกับ 4 ท่านนี้ 100%

5. Financial Review Items NOT CHANGED — for financial-reviewer

Found during design analysis; outside design scope per CLAUDE.md hard stops. Recorded, not modified.

IDFinding · affected cases · risk · recommended remediation
FRI-1Keyword-based direction fallback in ReportsService. src/lib/reports/reports-service.ts ~l.95: const dir = t.direction || (isExp ? "expense" : "income") where isExp tests the description for "จ่าย/ซื้อ/ค่า". Affected: any posted transaction with null direction; feeds getStatementOfFinancialPosition → monthly totals, category totals, getExecutiveFinancialSummary (the very source approved in Q5), Reports page, and — after Q5 — Dashboard/Transactions KPIs. Risk: an income described with "ค่า…" (e.g. "ค่าเช่าสถานที่รับมา") is counted as expense; silent misstatement of a financial report. HIGH if null directions exist; LOW if the column is NOT NULL — verify in supabase/migrations. Remediation: if the column is NOT NULL, delete the fallback; if nullable, treat null as a data error (exclude + surface a "รายการที่ต้องตรวจสอบ" count in provenance), never infer. Add a unit test with a "ค่า…" income row.
FRI-2Same heuristic in DashboardPage. src/pages/DashboardPage.ts loadData: direction inferred from description keywords for the 5 most-recent rows; totals labelled "เดือนนี้" derived from those 5 rows. Affected: dashboard monthly KPIs and the +/− sign/color on recent-activity rows. Risk: MEDIUM — misleading home numbers and a mis-signed row. Remediation: KPIs → Q5 source; row direction → read the real direction column (already selected in TransactionsPage). Design-adjacent: the render change is R4 scope, the query change needs financial-reviewer sign-off.
FRI-3Transactions KPI sums all statuses and all time. TransactionsPage.renderHtml sums this.transactions (draft, pending, rejected, voided included; no date bound) under "เดือนนี้". Risk: MEDIUM — overstated figures on a high-traffic page. Remediation: Q5 (approved). Listed here so the reviewer can confirm no other consumer depends on the old sum.
FRI-4Hard-coded chart scale. DashboardPage.ts maxVal = 5000000 satang (฿50,000) clamps trend bars; any month above ฿50k renders identical to ฿50k. Risk: LOW (visual only, but misleading). Remediation: derive max from data in R4.
FRI-5ReportsService.getExecutiveFinancialSummary month end = "YYYY-MM-31". String bound may behave inconsistently for 28/29/30-day months depending on Postgres date coercion of an invalid date. Risk: LOW–MEDIUM. Remediation: compute the real last day (or use < next-month-01). Verify with a February test before Q5 makes this the shared source.
