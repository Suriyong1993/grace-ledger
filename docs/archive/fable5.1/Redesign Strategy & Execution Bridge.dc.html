3. External patterns — principles, not visuals (Step 3 input)

ReferencePrinciple → user problem → relevance → adaptation → riskVerdict
LinearPrinciple: one dense, keyboard-navigable list per workspace with a right-hand detail that never leaves context. Problem: triage many items fast. Relevance: approvals queue and transactions lookup. Adaptation: row = target; detail as a URL-bound right sheet (/approvals/:id); ⌘K search on desktop only. Risk: density hurts non-experts on mobile — keep rows 15px/48px min and switch to full-screen sheet ≤768.ADOPT
StripePrinciple: money is typeset as data (tabular, aligned, sign-explicit), and complex objects are shown as a summary block followed by structured facts. Problem: verify an amount at a glance. Relevance: already partly present (.num-display). Adaptation: right-align all amounts in tables, ฿ in its own span, summary → facts → timeline order in sheets. Risk: none material.ADOPT
RampPrinciple: the home is an inbox of actions with the consequence inline (approve here, see policy impact here). Problem: approvers forget or approve blind. Relevance: two-person rule, projected fund balance. Adaptation: "รอคุณตัดสินใจ" rows carry fund balance-after and receipt flag; approve button in-row (foreground-filled, not orange) with confirm sheet. Risk: in-row approve invites accidents — keep the server guard and require the sheet for any deficit or missing-receipt case.ADOPT (guarded)
MercuryPrinciple: trust through restraint — few surfaces, hairline borders, generous whitespace, one accent. Problem: finance UI that feels safe. Relevance: matches DESIGN vibe "Calm · Exact · Quiet". Adaptation: two backgrounds, border-joined KPI strips instead of card fields, tint only for state. Risk: too quiet → status invisible; mitigate with the stepper and badges.ADOPT
VercelPrinciple: top-level scope switcher + flat tab navigation. Problem: multi-project context. Relevance: low — one church per session; sidebar + bottom nav already approved and tested. Adaptation: none; Concept C's top nav was explored and rejected for mobile parity. Risk: rewriting a working shell for fashion.AVOID

4. Recommended direction (Step 4)

RECOMMENDATION Concept B "งานสัปดาห์นี้" as the spine (1b), with A's density for lookup screens and C's fund-health table for Funds — reasoning in the Master Plan. The identity evolves; it is not replaced.

KEEP
  • Palette, Sarabun + Inter, fixed finance colors, .num-display
  • Sidebar + topbar + bottom-nav shell; hash routes
  • Shipped radius/height values (D1 → tokens)
  • Cash Count screen structure (stat strip, steppers)
  • Fund-impact-before-decision on approvals
  • Error/empty copy voice; AI drawer; login surface
  • All of src/lib, supabase, tests
EVOLVE
  • Home → this week's work (live round + decisions + quiet balance)
  • Offering session → one screen, 5-step stepper, one primary per step
  • Approval detail → URL-bound right sheet
  • Transactions → table ≥900 / rows <900, honest KPI labels, create sheet
  • Funds → health table; Reports → white surfaces
  • Type scale: titles down (22px), hero amount 32px, one per screen
  • Nav grouping: งานประจำ · บัญชี · ภาพรวม (routes unchanged)
REPLACE
  • Three status maps → one
  • Duplicate txn-row markup → TxnRow
  • Centered modal for multi-field content → sheet
  • Native date display → Thai date trigger
  • Tinted KPI tiles / orange numerals / orange bars → white + foreground
  • Ad-hoc channel badges (green/blue/amber) → amount rows
  • Fixed chart scale → data-derived
AVOID
  • Any framework, Tailwind, CSS-in-JS
  • Top-nav shell rewrite (Vercel-style)
  • Glass, gradients, springs, count-up numbers
  • Cards inside cards; four floating KPI cards
  • Decorative charts with thin data
  • New colors (blue leaves the UI except "posted")
  • Changing any business rule to fit a layout
