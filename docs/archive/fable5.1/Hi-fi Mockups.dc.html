Q5 — "เดือนนี้" KPI: investigation result

VERIFIED FACT. TransactionsPage.loadData() fetches all church transactions with no date bound and renderHtml() sums this.transactions across all statuses (draft, pending, rejected, voided included) under the label "รายรับเดือนนี้ / รายจ่ายเดือนนี้". DashboardPage sums only the 5 most recent rows and infers direction from keywords ("จ่าย/ซื้อ/ค่า") — same class of error.

VERIFIED FACT. A correct, scoped source already exists: ReportsService.getExecutiveFinancialSummary(churchId, "YYYY-MM") returns monthly_income, monthly_expense from posted ledger rows within the month, with provenance and excluded states.

RECOMMENDATION. Do not relabel. Both pages consume getExecutiveFinancialSummary for the two KPIs (one extra read, no new query logic). The transaction list itself stays unfiltered (it is a ledger browser). Label stays "เดือนนี้" and gains a provenance hint: "จากรายการที่ลงบัญชีแล้ว".

OPEN — flag to financial-reviewer, out of design scope. ReportsService line ~95 also falls back to keyword inference when direction is null. Direction is a real column; the fallback should be removed or made an explicit error. Reported, not changed.
