# Projected Balance formula: posted balance + approved-unposted + evaluating transaction

When an approver decides on a pending transaction, Grace Ledger warns if approving it would push a fund into deficit — but checking only the fund's posted `current_balance` would miss other transactions that are already approved but not yet posted, letting several approvals each look individually safe while collectively overdrawing the fund. `ProjectedBalanceEngine.calculateProjectedFundBalance` (`src/lib/transactions/projected-balance-engine.ts:110-112`) therefore sums three terms — posted balance + net effect of all other approved-but-unposted transactions on that fund + the net effect of the transaction being evaluated — using the sign convention income/transfer-in = positive, expense/transfer-out = negative (`src/lib/transactions/projected-balance-engine.ts:12-17`), and surfaces the three-part breakdown directly in the approval UI (`src/components/approvals/ProjectedBalanceCard.ts`, wired via `src/lib/transactions/approvals-service.ts:212-223`). Rejected alternative: check only posted `current_balance` at approval time — simpler, but reopens the race where a fund with a large approved-but-unposted expense still shows a healthy posted balance to the next approver, so two approvals can each pass individually and jointly overdraw the fund.
