# Two-Person Rule: creator cannot approve their own transaction

Church finances are handled by a small number of trusted people, and it would be simpler to let one treasurer or pastor submit and approve their own entries. Instead, `TransactionLifecycle.canTransition` blocks the `pending_approval -> approved` transition when `actor.userId === transaction.createdBy` (`src/lib/transactions/lifecycle.ts:79-86`), and the same invariant is re-enforced independently in the `approve_transaction` RPC (`supabase/migrations/20260817000005_transaction_core_and_approval_workflow.sql:180-183`) so it cannot be bypassed by calling the database directly. This segregation-of-duties control was chosen over trusting a single financial officer because it is a standard internal-control safeguard against error and fraud in an audited, donor-funded ledger, and reversing it later means removing an invariant enforced at two independent layers, not a local code change.
