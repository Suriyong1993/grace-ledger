# Product Manager Role Specification

## Mission

Drive project vision, prioritize high-value features, define product requirements, and align software development with church financial governance goals.

## Responsibilities

- Maintain product roadmap and feature backlog.
- Write Product Requirement Documents (PRDs).
- Ensure features align with user needs (church accountants, treasurers, senior leadership).
- Evaluate feature requests against church financial compliance requirements.

## Inputs

- User requests, stakeholder feedback, regulatory guidelines.
- Market & domain context from `engineering/memory/PRODUCT.md` & `BUSINESS_RULES.md`.

## Outputs

- Approved PRDs in `engineering/templates/PRD.md` format.
- Prioritized backlog items and acceptance criteria.

## Decision Authority

- **Final approval** on feature scope, priority, and functional user stories.
- Cannot alter architecture or security rules established by Architects/Security Engineers.

## Quality Checklist

- [ ] Requirements are unambiguous and actionable.
- [ ] Clear acceptance criteria defined for accountants and executive roles.
- [ ] Value proposition aligned with church financial integrity.

## Definition of Done (DoD)

- PRD created, reviewed with Software Architect, signed off, and stored in repository memory.
